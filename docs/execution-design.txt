一、建设目标与边界

执行层提供两个确定性能力：
1. 盘前validate_plan：把策略已经决定的买卖意图、预算或比例，转换为数量/限价/顺序确定、符合交易约束且预留可计算的订单。
2. 盘后match：使用账本中的冻结计划、原订单资源及目标日真实日线事实，输出逐单模拟成交、明确未成交或等待事实的结果。
执行层不选股票、不排名、不优化利润、不调用LLM、不采集网络数据、不直接写账本、不生成HTML。是否支付、增减持仓、产生FIFO成本、权益与税务均由账本负责。执行费用计算与账本复算使用同一中立纯函数，业务责任仍分开。
当前覆盖普通沪深主板A股、限价意图、开盘价参考、全额订单、固定盘前预算。无真实券商连接、融资/卖空、盘口排队、逐笔回放、市价单、盘中追单、部分成交或同日第二次决策。执行纯计算器按account_id契约工作；当前外层配置/CLI已按SI01读取持久登记账户，决策证据SX01已完成，见第十六节。
未知来源事实的正确结果可以是等待；明确不支持的交易日/证券状态应给出确定的政策原因，不让它永远伪装成下载失败。每个状态都有后续动作及报告字段。

二、依赖与职责分配

策略 → 提供账户、目标日、买卖/HOLD意图、理由、预算/比例/数量、限价及确定顺序。LLM格式与语义纠错、规则策略排名、目标持仓权重及调仓父目标属于策略层。
数据 → 公开prices/security/calendar/calendar_operation/pool/events/event_coverage/readiness/read_snapshot等提供事实与证据；不替执行层决定买卖。
账本 → 提供一致的规划状态、冻结计划、执行资源视图、订单状态；freeze_plan原子保存预留，apply_execution_results唯一入账。
执行 → 输出计划验证报告和PlanEnvelope、或逐单ExecutionResult；不以返回“模拟成交”代替账本提交成功。
调度/应用入口 → 组织读取、显式冻结市场证据、策略调用、验证、账本封存、原单补核、提交、权益/日结及页面。框架不属于执行纯计算器，不能借此增加循环导入。
展示 → 消费账本与验证/执行报告，展示原因、金额、规则与证据；不在页面重新计算费用或改变结果。
共享domain及common纯计算模块不是新增业务层；不得导入数据仓库、账本存储、模型、策略或报告实现。

四、日期、输入时点与运行时间轴

D = 计划使用的最近已完成行情日；N = 下一目标交易日；Kp = 实际盘前输入知识截止；Ke = 盘后/补跑结算知识截止。行情日期与实际取得时间分开。
盘前：D日18:10取得合格数据并结清D及之前必要账务 → 读取N生效的候选池、账户和策略意图 → validate_plan → 账本在N日09:00前原子封存。也可N日09:00前开机完成，但不能使用N日未来行情；D应为N的前一真实交易日。旧数据未补齐时不悄悄用更早行情生成当前方案的新计划。
盘中：本模型没有新增决策，电脑无需保持开机。
盘后：N日18:10或下次开机 → 补齐最早未完成目标日的输入 → 处理该日应先生效的必要股份/除权事项 → 读取原冻结计划及执行视图 → match → 按盘前冻结的SELL→税负评估→BUY顺序逐单提交 → 登记日资格、其余已到期权益/税、日结及页面 → 生成下一交易日计划。
18:10只是最早终态处理门槛，不保证来源届时发布齐全。终态须满足N日18:10 <= Ke <= computed_at <= 实际处理时点；09:00整不再封存。所有判断转Asia/Shanghai，存储时间带时区。生产时钟不接受输入伪造；受控时钟仅用于隔离验收。
补跑按目标交易日升序。只有之前确实封存的单可以计算；无计划日不调用match造单，合法空计划不调用非空结果批量入口，两者仍可处理权益/日结。WAITING不把有效期延长到新日，五日调仓父任务不因关机延长。

五、盘前意图、数量与计划校验

1. 输入规范
StrategyProposal含proposal_id/account_id/strategy_id/strategy_version/target_session/market_as_of/generated_at/input_cutoff/account_snapshot_id/account_revision、ordered_intents、no_order_reason、可选rebalance_task_id。现实现通过SX01保存provenance_mode/decision_ref及策略计算来源；Envelope/FrozenPlan使用strategy_market_snapshot_ids/strategy_data_evidence，与执行资格data_evidence分别保留。strategy_version是必填的策略身份，不是另一套运行程序。
每个意图含code、BUY/SELL/HOLD、reason、order_index和限价；不另设priority别名。BUY在quantity与budget_fen二者中明确选一，SELL在quantity与sell_fraction二者中明确选一。预算是“本次新增买入的含费现金上限”，不是目标持仓总市值；目标权重差额由策略先转换。SELL比例针对本轮确定可卖股数，不含应收股份、不可卖T+1批次或其他卖单预留。验证器将rebalance_task_id显式映射到PlanEnvelope.task_id；若该关联非法则拒绝，不能直接透传错名后丢失多日调仓关系。
价格/比例只接受Decimal或十进制字符串，分金额与数量只接受整数，不接受bool/float、NaN、无穷或负数。代码标准化但不擅自换市场或代找近似代码；限价必须正且为0.01整数倍，不能自动改成更激进价格。同一代码出现矛盾或重复意图拒绝整份输入。
HOLD不建订单；去除HOLD后、任何SKIPPED筛除前，代码数按冻结execution policy及真实strategy_id核验。旧无scope政策保持全账户最多五个BUY/SELL代码；新LLM_ONLY仅S1/S1-LT无每日只数截断，LLM仍买卖合计最多五个。受五只约束时，第六个意图即使将被SKIPPED也整份拒绝；不替策略改方向或暗自合并。NL变更状态及验收见末节。盘前按固定政策将SELL排在BUY之前，同方向保留输入顺序，并把最终顺序冻结；盘后遵守此顺序，不按收益挑单。这样卖出触发的税务先进入买入资源守卫，不表示卖款可用于原买单。

2. 买入资格
读取Kp前可知的D行情、证券身份、N生效候选池和交易日历。只新增沪深主板A股，截至D已上市至少121个交易日；使用截止D的真实121交易日窗口与上市日比较，无需下载上市以来全部历史。候选池不是永久交易许可证，盘前重核D的ST/交易状态、上市/退市信息和已知复杂事项；已有持仓退出不要求仍在池内。
目标日N晚间按N实际生效事实复核新增买入：明确ST、退市整理、已退市、非允许板块、N日生效且影响本单的复杂事项或本模型不支持的无涨跌幅日，按确定政策拒绝；未知相关状态、相互冲突则等待。未来复杂事项的买入排除以冻结Kp证据为准，不用Ke才知道、N开盘后新公布的未来事项追溯取消N原单；例如N+2公告影响N+5，只约束后续计划。退市整理历史状态无生效证据时不由新名称猜测；当前免费源覆盖范围必须随证据保存。
KNOWN_ONLY_COVERAGE：只拦截已知复杂事项；不要求免费源证明全市场所有复杂事项均不存在。对当日价格或股份有不能排除的影响时仍待核，不通过放宽资格绕过价格/资产未知。

3. 买入数量
budget_fen是含费上限。求最大的100股整数倍q，使q<=普通限价单单笔上限且q×limit_price+按N政策计算的买费<=budget_fen。用整数/Decimal有界求解并在最后复算，禁止先除价格再让最低佣金挤穿预算。显式quantity不自动缩量。
预算不足一手生成SKIPPED/BELOW_ONE_LOT，不制造0股订单。所有有效买单限价含费预留之和必须<=账本确认的可用现金；不能使用同开盘卖款、未到现金红利、未兑现权益，也不能依输入先后抢占预算后偷偷缩后单。合计不足为INVALID_PLAN，由策略在截止前处理。

4. 卖出数量
使用目标日可卖量V及原始批次；普通买入次交易日可卖，用来源日历而非自然日。已到股且可卖日期明确的股份按账本提供量计算，未到股份不预卖。
显式q须q<=V，且q%100==0或q%100==V%100；非整手部分一次处理剩余零股。例V=1150可卖100、150或1150，不能卖125；V=50时只能卖50，不能拆25。
比例p满足0<p<=1，先得floor(V×p)，再取不超过该值的最大合法q；没有合法正数量则SKIPPED/BELOW_SELLABLE_LOT。保存V、p、未取整数、实际q和取整原因。全部卖出p=1包含零股。显式数量非法则拒绝，不能偷偷调整。
单笔最高1,000,000股；超上限拒绝，不自动拆单绕过单代码一单或重复最低佣金。ST、退出候选池、已知未来复杂事项等买入排除条件不自动禁止已有持仓在合法普通交易日退出。

5. 验证状态与封存
结构/规则矛盾、重复代码、六代码、非法显式数量、过期状态或合计预算不符：INVALID_PLAN/INVALID_INPUT，整份不封存。账户或任何拟执行意图的必需事实未知：WAITING_VALIDATION，不把未知意图偷偷删掉；其它账户可继续。
明确项目排除或金额不足一手：该意图SKIPPED并留原因，可与其它合法单组成验证成功计划；没有订单时生成合法空计划和逐项原因。此为事先固定的验证政策，结果必须完整呈现，不是盘后挑选交易。
成功输出PlanEnvelope、逐单预留需求、总预算、账户输入摘要和ValidationReport。调用成功不表示封存成功；只有账本freeze_plan回执才确认冻结。账户修订变化时必须重新读取并重新验证，不能只把expected_revision改新而沿用旧预算。

六、盘后撮合决策与状态表

输入必须是账本get_plan/专用执行视图返回的FrozenPlan，保存原plan_hash/frozen_at/order_ids/target_session、全部政策与固定buy_budget_fen；拒绝拿StrategyProposal或旧TradingPlan作为冻结事实。原计划内orders是封存原文；当前订单状态须读execution_view.orders或orders(account_id,plan_id=...)。已经FILLED/NOT_FILLED的单直接复用账本保存结果，不因新行情重新撮合。
逐单先检查身份、时点、原政策、所用证据完整性及处理顺序。对已有充分证明的未成交原因，按下表先后选择主要原因，保留其余已证实原因；尚未知的其他条件不抢在独立成立的否定证明之前。既无确定未成交证明、成交必需事实又不全时才等待；成交须全部正向条件满足。不能用已冲突或损坏的价格证明限价不符，也不能为短路而丢弃会推翻该证明的相关异常。

例如可信目标日open已高于原买入限价，即可用execution_context=null及该价格的完整证明返回LIMIT_NOT_MET；无需为这个否定结论补齐ST或涨跌幅。NO_TRADES/INSUFFICIENT_DAILY_VOLUME同理使用可信量的最小证明；它们不授权任何成交。执行器只提交用于该决定的完整依赖，其他用途的未知/损坏另作诊断，不能把无关问题扩散到所有订单。
volume必须是已标准化为股的可信非负整数；当没有其他独立充分未成交证明、仍须据量判断时，缺失、单位不明或冲突返回WAITING_DATA，不从成交额反推。三个独立模拟账户不共同消耗这份历史总量。日总量仅用作不可能成交的上限/零量检查，不证明开盘流动性，不据此模拟排队、部分成交或设置复杂参与率。不得用high/low/close替代开盘价，也不得用复权序列作为成交价。
开盘等于限价可成交；涨停卖出、跌停买入在其它条件满足时可模拟成交。涨停拒买/跌停拒卖是项目保守政策，不声称交易所法律禁止这些方向。
已知无涨跌幅限制日：当前模型不新增买入，也不模拟已有持仓在该特殊日卖出，统一明确MODEL_UNSUPPORTED_SESSION、零费用并保留持仓；后续普通交易日可重新提出新计划。未知是否特殊日且没有其他独立充分未成交证明时等待。不得填0上下限或默认10%。
本模型是日线开盘价参考；open可能来自集合竞价或之后首笔，不确定实际成交阶段，也不模拟连续竞价即时申报基准，因此不套缺少逐笔依据的连续竞价价格笼子。本系统也不声称以日线还原真实委托受理、集合竞价队列或成交保障。

七、政策、涨跌停、除权与费用

1. 一个可追溯政策包
configs/execution_rules.toml（已实现并验收）管理当前支持规则的rule_id/市场/板块/证券类别/有效起止日/知悉时间/来源条款/价位/买入手数/单笔上限/涨跌幅或无上限条件。只维护一套解析器，不在数据层再复制法规注册表。
冻结时保存完整规则注册表的相关项、解析器标识和摘要、当前模拟政策及费用政策。目标日实际ST/特殊状态由被冻结的解析规则和N日证据确定，不能盘后随手换一个context。未来官方政策变化按生效日期维护；不覆盖旧单政策。发现冻结政策与目标日确定的法定规则冲突时进入RULE_POLICY_CONFLICT维护，不用旧错误规则成交，也不擅自改过去决策。
每个execution_context含code/exchange/board/security_class、rule_id/effective_from/effective_to/known_at、price_tick、limit_rate或no_price_limit、special_status_unknown、ruleset_hash及状态推导证据。数据核验事实、计算价格基准；执行器核验政策适用性；账本绑定原冻结政策、上下文及结果摘要。
正式首个观察日由activate_simulation显式确定，只支持从已核查规则覆盖区间开始的前向运行；不以实现任意历史年份撮合作为前置条件。早于已支持规则区间返回RULE_NOT_COVERED，不能假装回测。

2. 价格基准及边界
普通日以来源未复权preclose为参考；存在可信相邻交易日收盘时交叉核验。缺实际前收但正常日源preclose有完整证据，可以明确标source_unadjusted_preclose_only；若已查询到CORRUPT/CONFLICT不能退回此口径隐瞒。日历或前收未知在除权日须等待。
简单现金/送转除权使用已实施条款及真实前收，分别保存R_exact=(真实前收−每股现金红利)/(1+每股送股+每股转增)、来源参考价及最终选用的R，不覆盖成同一个两位数。正文明确对最终涨跌停价格ROUND_HALF_UP到tick，未给中间参考价提前舍入的依据；本项目保留已确认精度计算U=round(R×(1+rate))、L=round(R×(1−rate))，有正式公布边界或精度依据时优先核验。若来源与公式的精度差异会产生不同最终涨跌停价，返回PRICE_REFERENCE_PRECISION_PENDING，不凭0.011容差擅选。例如R_exact=9.995、10%，直接上限10.99，先舍入10.00则上限11.00，必须待核其正式价格基准。
若计算涨跌幅价格与已确认基准之差不足一tick，按相应增/减一tick；下限至少一tick。例如tick对齐基准0.04、10%、tick0.01，应为上限0.05/下限0.03。非tick基准涉及极低价保护且运算顺序无法确证时待核，不另造多轮舍入规则。非有限/非正基准、上下限倒置或N日OHLC越过合法范围均不冒充READY。
现行沪深规则自2026-07-06起普通主板及主板风险警示股票均按适用10%规则；不能把当前ST机械套5%。本项目仍不新增ST买入，但已有ST持仓退出需要正确的目标日规则。上市前五个交易日、重新上市首日、退市整理首日等无涨跌幅情形须显式识别；事实未知不猜测。
盘前限价定义为N日不复权元/股价格。Kp前已知的除权信息可供策略形成价格，封存后不自动复权改价、加股或改数量。目标日实际价格范围导致原限价不合法时明确未成交；未知条款则等待。

3. 费用
当前佣金为项目假设：成交额×0.0003，最低500分，全佣不重复叠加交易所费用；卖出印花税0.0005、买入0；过户费双向0.00001。逐项Decimal ROUND_HALF_UP到分，费用和为各分项之和。没有成交不收任何交易费用。
BUY净现金=−成交额−佣金−印花税−过户费；SELL净现金=成交额−全部费用。盘前预留使用限价与全量q算最坏买费；成交使用open与原q，节省部分由账本释放但不允许给其它原单加量。
费率选择按N，而不是程序实际补跑日；含有效起止日、来源/假设标签、known_at及摘要。没有适用项则WAITING_RULE。冻结后全程使用原费率包；不得套运行日的新费率重算旧成交。
纯费用数学已从ledger/evidence.py提取至common/fees.py，账本已调用、执行器已复用；该移动及公共异常适配属于已完成LX05，不改变金额公式。1000股×10元买入现金39994.90，之后10.30元全部卖出现金50284.65、双边费用15.35须继续成立。

八、账本执行视图与阶段顺序（LX01已实现并验收）

account_state(target_session)是当前规划/展示视图，不能冒充历史开盘现金；can_plan=False可能只是已有计划或错过盘前截止，不能据此取消原单。
新增公开execution_view(account_id,plan_id)，在一个只读事务返回FrozenPlan、当前订单状态及已提交结果、逐单原预留、冻结批次分配、账户输入证据、原总买入预算/已耗金额、当前事务修订、前序水位/未决依赖及当日开盘前应生效权益调整。执行计算器只接收该DTO，不逐表读取账本私有SQL。
同时明确两个口径：
• original_resources：盘前冻结的确认现金/已知负债、固定预算、可卖批次及原预留。是原单可用资源依据，不能被N+1红利、N日同开盘卖款或后来低价成交释放额增大。
• commit_guards：当前账本可支付现金、其它原单预留、已知/未知税款、批次完整性和处理顺序。是本次能否安全提交的检查，不是用来重新求原订单数量的资金输入。
不建设通用逐笔历史资金重放引擎。正常按最早未完成日期推进；执行视图只承诺在前序水位及事件阶段满足时可判定。已经混入后日依赖、无法确定旧日资源影响时返回WAITING/CONFLICT和可定位原因，不能把当前总现金硬当旧日开盘资金。
当日应生效的股份上市/除权成本在撮合前由账本处理并记录阶段证据；登记日持有资格在当天交易之后确认。冻结原股数量及批次映射不凭空扩张；新到股份只有此前已合法冻结的可卖量才能用于原单，不能事后增量。若权益改变原批次关系，须由账本提供守恒映射，否则待核。
盘前冻结的提交次序为SELL→每笔卖出触发的税务评估/待核→BUY，同方向顺序不变。已确定合法卖出可以入账；存在未确定卖单或新增未知税负时，依赖该资源的买单保持WAITING_DATA，不先买后补税。已知新增税负也须检查是否侵占原可用资源，不以同次卖款补足原预算缺口。apply_execution_results每单必须在写事务重验现金、其他预留、税款及批次；前单或权益改变修订后，未提交单重新读取守卫，不得只换expected_revision沿用旧结论。原市场判断、数量、限价及总买入上限不变。
自有预留必须单列own_reserved_cash/shares、other_reserved_cash及frozen_lot_allocations；不能扣了自己的预留后又说资金/股数不足。已提交订单的资金/股数变化只作为已完成事实，不能重复扣。
execution_view顶层state/issues是全计划汇总，不是“所有单一律停办”的开关。逐单读取orders中的issues/can_submit/max_payable_fen和原预留；某证券权益待核不自动阻止另一证券合法卖出。同方向按冻结order_index遍历、输出和提交，但一单WAITING不要求其余独立同方向单也等待；未决SELL对BUY的阶段守卫以及全部资金/批次守卫仍严格保留。确定未成交按最小证明终结，不要求成交资源守卫先READY。
资金不足统一口径：盘前明确不足拒绝建单；冻结后原预留/资产/新税负冲突属于资源待核，不自动以NOT_FILLED释放，也不能在后来到账后拿新资金让旧单成交。明确停牌、价格条件不符等市场原因可以独立终结。总架构此前“资金不足一概未成交”相应修正。

九、公共输入输出契约

继续在中立domain.py定义或导出同一套业务DTO，字典与dataclass有统一适配，禁止一个名称对应两套字段。日期ISO、时间带时区、Decimal字符串、金额整数分。
• StrategyProposal/ExecutionIntent：第五节全部意图字段。原占位TradingPlan/TradeIntent已直接替换为该规范，两个Protocol同步，没有第二套可选入口。
• PlanValidationResult：status、validation_id、proposal_hash、account_snapshot_id/hash/revision、D/N/Kp、accepted_orders、skipped_intents、issues、required_inputs、policy_bundle/hash、market_evidence、PlanEnvelope或null。
• PlanEnvelope：冻结输入；保留原字段，补账户快照摘要、验证报告及跳过项、规则注册包、目标池引用、日历证据。不是已冻结证明。
• FrozenPlan：冻结输出；除输入外必须含frozen_at、plan_hash、account_revision_at_freeze、buy_budget_fen、完整orders/reservations引用、fee_policy_hash/rule_policy_hash/ruleset_hash、不可变文档引用。
• ExecutionAccountView：第八节两种资源口径、逐单状态、前序/权益阶段、实际读取修订和issue列表；不可仅传一个bool can_plan。
• ExecutionMarketBundle：按code/target_session/Ke保存prices、security、events/coverage、calendar、execution readiness及完整context，各查询带参数、结果、observation_ids、快照集合和摘要；允许每股使用不同适用规则。
• ExecutionBatchResult：现有账本apply_execution_results的提交回执，字段为state/completion_status/results/order_states/account_revision，实际批量回执另含submission_order。它只描述本次提交集合，不是纯match的计算输出，也不能用子批次COMPLETE宣称整计划完成。计算证据中的plan_hash/bundle_hash、逐单原因及提交关联由外层报告保存，不另造同名DTO。输入/协议错误可能仅返回state/reason，调用方须先检查state再读取完整批量字段；不得假设每个错误都有completion_status。
• ExecutionResult：result_id/order_id/plan_id/account_id/code/side/target_session、state、reason_code/reason_details、execution_model、policy hashes、execution_context或该原因的最小规则上下文、Ke/computed_at、数据证据和账户执行视图引用必填。日期/核心ID不可用None假装默认值。
  SIMULATED_FILL：quantity=原q，price=open，amount/commission/stamp/transfer/fees/net_cash各为复算值；账本核验OPEN_PRICE_MATCH的最小价格证明，不接受任意满足限价的另一成交价。
  NOT_FILLED：quantity及所有金额费用=整数0，price=null；原因须有对应最小证据。
  WAITING_DATA：quantity/price/所有金额费用=null，附缺口和重试条件，不收费用、不释放预留。
纯流程错误使用INVALID_INPUT/STALE_ACCOUNT/NOT_DUE/CONFLICT/INTEGRITY_ERROR，不写成交易拒单。数据DataResult的CONFLICT可作为待数据的源冲突原因；账户提交CONFLICT为维护错误，分层保留。

已实现接口：PlanValidator.validate_plan(proposal: StrategyProposal, account_snapshot: dict, market_evidence: tuple[MarketQueryEvidence, ...], policy_bundle: dict, *, now: datetime) -> PlanValidationResult。account_snapshot必须保留LedgerService.account_state返回的全部原始字段；数据证据含D行情、N目标池、真实日历、身份及事项，逐项绑定Kp，policy_bundle由现有common.policies构造。账户摘要采用账本已定义的规范化摘要口径（只排除snapshot_at/report_revision/last_rendered_revision），通过跨层验收与实际冻结一致，不用删减后的策略展示对象代替原账户。计算器不读写库/网络；外层先取得证据再调用。now由生产外层的真实时钟提供，隔离测试可注入；账本封存仍在事务内独立复核真实时点、账户和证据，不能信任客户端now越过截止。

开发细化（SUPPORT-10，属于LX01/LX02）：ExecutionResult另携有界account_view_evidence见证（evidence_schema=2）；先经统一compact_view_evidence投影，将完整冻结计划换成原件绑定、订单结果换成经济摘要，再计算覆盖见证的view_hash，排除snapshot_at与view_hash自身。旧见证沿其原摘要口径兼容核验。账户输入摘要仍排除读取/展示时点而覆盖全部财务字段。入账核验原view身份、修订区间、冻结计划与原资源，历史view仅审计；批量可共用初始view，每单事务重新计算当前守卫并保存commit_guard_hash及修订，不能仅换expected_revision。无需新增视图表或历史资金回放。原Kp证券/事件公开查询作为security_facts/event_facts随计划保存；未来复杂事项的盘前已知证明取原事件证据，不以刷新后available_at推断过去知悉时间。恢复隔离目录携带现行非密钥执行规则配置，原单仍用自身冻结政策。

十、确定性、证据、幂等与恢复

盘前证据用D行情及Kp，目标池用pool(N,Kp)独立公共查询；不能仅使用freeze(D)附带的pool(D)作为月末新池。security/pool/calendar等已有公共查询证据可以组合，不新增第二套市场快照系统。
证券身份保存盘前事实；补跑时不得用后来名称推断目标日历史ST/退市整理。ST优先使用N日bar的按日事实；具有明确日期的上市/最终退市事实可按日期使用。缺少特定历史状态就保留未知，不通过全量重下行情伪装补齐。
证据组装对本轮固定同一Ke，逐证券保存prices/security/events/event_coverage/calendar_operation的原始DataResult、参数及观测ID，再推导各自context并调用readiness(...,purpose="execution",rule_context=context)。综合readiness可能把覆盖损坏概括为EVENT_COVERAGE_UNKNOWN，因此必须保留原event_coverage的CORRUPT/冲突/刷新不足等细节，区分修复、重试与来源待核；不能只依综合ready布尔值决定处置。
freeze一次仅接受一份rule_context。需要持久化执行证据时，由有写入职责的外层逐股调用freeze([code],N,knowledge_cutoff=Ke,purposes=("execution",),rule_context=contexts[code])，再组合快照集合；不得让不同证券/市场/状态共用一份context。freeze会写文件与索引，默认只读CLI只可用公开读取及read_snapshot/evidence_manifest核验已有快照，不偷偷freeze。这些均为既有数据接口的调用规则，不新增采集接口或改变采集流程。
业务结果摘要覆盖原单、实际用于判断的政策/行情/账户资源证据和原因，排除每次变化的computed_at/日志时间/当前expected_revision。同一完整输入得到同一结果标识；不保证对后来的新订正事实产生相同未决结果。
每个订单独立事务；完成一个不要求其它单同时成功。attempt_id覆盖本次证据/状态，WAITING重放仍是WAITING，不占用经济终态键。新证据新attempt可以完成原单；终态重复提交相同完整结果无副作用，异结果CONFLICT。
批量外壳逐单读取/推进当前revision，不从旧ALREADY_APPLIED回执取旧revision覆盖游标；根据original_state和账本当前单状态聚合，重复WAITING批量仍PARTIAL。程序中断后先读已完成状态，不能依内存决定扣款。
一次初始match可能因SELL_PHASE_PENDING把BUY标为WAITING。提交已有充分证据的卖单、账本完成其税负评估后，应用必须重读execution_view，并只对仍未终态且依赖已变化的原单再算；不能把初次WAITING结论只换修订号提交。若本轮出现订单终态或相关权益/税阶段进展，可继续下一次重读；没有新进展则保存待办、原因及重试条件后退出，禁止对同一输入忙循环或反复写WAITING。整个过程不重问策略/LLM，不改原单数量/限价/顺序、不使用新现金扩张原预算。
整计划汇总以最新execution_view.orders或orders(account_id,plan_id=...)的全部订单为准：全部终态才COMPLETE，任一未决则PARTIAL；协议/完整性/提交错误单独保留ERROR诊断。某次子批次COMPLETE只说明该集合完成。空计划不调用非空批量接口，由应用明确记录“合法空计划”；无计划另记“无计划”，两者都不伪造成交。
来源订正：未结原单按新事实补核，始终使用原数量/价格/政策；已完成原单不自动重撮合，进入现有账本更正/冲突流程。报告或CSV失败只重建展示，不重复撮合、采集或调用模型。
输入/输出文件原子写；请求与响应不含密钥。只读计算失败保留调用方证据，不清空账本。账户A待数据不阻塞账户B；同账户前序依赖不明不得绕过水位生成后日交易。
