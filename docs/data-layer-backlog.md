## 边界与唯一公共契约

数据层有两类能力：一类是供其他层调用的只读服务，另一类是显式采集、校验和持久化。它不读取账户来猜需求、不生成买卖意图、不调用模型、不依赖页面成功。调用方将持仓、订单、未付权益相关证券传入 `DataRequest`。

- 公开接口：`market.service.MarketDataService`；请求/返回：`market.contracts.DataRequest / DataResult / MarketSnapshot`。策略、执行的接口也引用这一个快照契约，已移除旧的空占位行情类型。
- `prices / calendar / calendar_operation / security / pool / events` 提供原始事实；`readiness` 按用途返回 `READY / PARTIAL / MISSING / WAITING_DATA / CONFLICT / CORRUPT`。
- `valuation` 为目标日未复权价格；`llm / rules` 为 21 / 121 日调整价格；`execution` 为目标日状态及明确规则上下文下的价格参考；`events` 为已取得事件视图；`event_settlement` 检查相关事件是否足以交账本处理；`index` 提供指数及日涨跌。
- `freeze / read_snapshot / revisions` 提供快照、完整性复核及字段修订差异；`evidence_manifest(snapshot_ids, observation_ids=...)`为备份只读导出核验过的快照、原件递归依赖、摘要和索引需求。读取从不联网；只有 `update` 或显式采集命令可能访问来源。
- 原始事件 `READY` 不表示可以结算，`CONFLICT` 也不自动阻断所有日期。用途查询先筛目标日/窗口相关事项再校验；`event_settlement` 默认检查目标日登记/除权/付款/股份上市及未定日事项；已登记但未到账的历史事项由账本传入 `event_ids` 持续追踪，相关冲突仍严格拒绝。账本根据持仓资格、实际到账日期和税规则记账。`execution` 需要调用方提供有效的 `rule_context`，数据层不擅自把所有日期设成10%涨跌幅。
