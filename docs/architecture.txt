二、确实存在的限制，以及如何落地

1. 电脑关机时业务不运行；云端仅展示最近成功上传的静态页面，不能保证每天准点完成业务，也不能保证每天有新的 LLM 判断。
处理：18:10达到日终数据门槛；自动业务17:00—19:00避让，19:00后首次检查或开机自动补处理。已经在目标日开盘前保存的订单，之后可以补取数据结算；没有事先计划的日期只能记“未生成计划，无新交易”。已有持仓继续估值、处理权益，不倒填 LLM 决策。如果希望每个交易日都有新的 LLM 计划，需让本机在相邻两个交易日之间至少有一次足够长的联网运行窗口；不要求白天开机或人在场。

2. “每日有计划和报告”可作为正常在线时的目标；“每日一定同时买入和卖出”不可保证。
首日没有可卖持仓，T+1、资金不足、停牌、限价不满足和涨跌停也可能阻止成交。LLM 策略在条件允许时主动提出买卖，不能为制造流水而违反规则。无成交也必须显示具体原因，不能只给空白页面。

3. 网络正常也不等于免费数据一定成功。
服务端限流、维护、更新延迟、空响应、字段修改、数据错误和来源停用都可能发生。AKShare 官方文档也明确说明目标网页变化会造成接口异常。设计目标是缓存、有限重试、备用源和自动恢复，而不是承诺永不失败。

4. 除数据外也不能绝对保证没有软件、磁盘或模型异常。
可实现的要求是：正常流程无需人工指挥；已知异常有明确状态和恢复路径；重复运行不重记账；异常不伪造成交或清空资产；报告可以重建。来源永久改版、硬盘损坏或真正的代码缺陷仍可能需要维护。

5. 免费日线不能证明任意时刻、任意限价单一定成交。
当前方案采用明确的“开盘价参考撮合”，不做盘口排队、盘中逐笔或最高最低价择优成交。它是保守的日线前向模拟，不是对实盘成交的复刻。这个精度与本次需求相符。

四、按现实时间运行的一个完整循环

以下以19:10开机后的正常顺序示意，不是固定耗时承诺。18:10已达到数据门槛，但自动业务17:00—19:00避让；后一步须等前一步满足条件，若20:00才开机则从20:00顺序执行。

首次安装完成时
建立三个账户和稳定页面。各显示本金 50,000、现金 50,000、持仓 0、累计费用 0、尚无成交；有数据则准备下一交易日计划，没有数据则显示等待数据。初始化当天不冒充一个已完成的交易观察日。
正式启用另存simulation_start_session，选择尚未到09:00截止的已知交易日；121日历史行情用于策略，不生成历史收益账。启用后无计划/零成交日也须保留真实交易日账单。

交易日D，18:10到期；19:00后首次检查（例如19:10开机）：程序检查待办
先读取交易日历和上次状态。有更早尚未处理的日期，先按日期顺序恢复。非交易日可恢复欠账和展示页面，不新造交易日。程序从已有缓存补缺，只请求必要行情、状态与持仓权益数据。

D，采集及历史恢复完成后：结算今天
先按D日有效日期处理已到期的股份可卖状态及除权应收，再读取D开盘前已冻结计划，用D不复权日线和相关状态判断成交、未成交或待数据，按盘前冻结的SELL→税负评估→BUY顺序逐单提交；未知卖出税负或未决卖单使相关买单资源待核，不先买后补税。登记日资格取D日交易后的持仓，处理现金/股份到账和税款，最后收盘估值、对账。即使卖款或红利先入账也不扩大D日冻结买入预算；完整调用顺序见账本附件第十节。程序不让LLM解释或决定今天是否成交。

D，当日日结后：发布今日账本
立即刷新稳定页面，展示今日买卖、金额、股数、手续费、余额、持仓和未成交原因。即使第三策略稍后失败，今天的账本也已经可见。数据未齐时页面显示最新可靠账和暂估状态。

D，日结及必要报告完成后：准备下一交易日N的计划
S1/S1-LT 按自己的固定规则计算；LLM 策略调用一次模型。程序检查股票资格、数量、现金、T+1、限价和订单上限，保存最终计划及输入快照。通常前一晚就完成，不需要用户早晨发指令。
计划封存或确定失败后，再用最新账本快照刷新下一日计划、预留及原因；此页面更新失败也不回滚账本或重问模型。

N，09:00 前：计划截止
这是本方案选择的保守技术截止，早于开盘集合竞价；不是新增证券法规。程序若此时才补跑，仅可使用已经完成的前一交易日数据与已结算资金。09:00 后不能为 N 新建、替换买卖计划；未及时完成就记录 N 无新计划。晚间再正常生成之后的计划。

N，市场开盘：规则在模拟中生效
电脑不必开机，也没有真实委托。晚间将用 N 日线中的开盘价检查原计划。该字段可能来自集合竞价或之后首笔竞价成交，不把它伪装成精确 09:30 的可成交盘口。记录“目标交易日＋开盘价参考”，不编造逐秒成交时间。

N，18:10到期，19:00后首次检查或下一次开机
采集 N 数据 → 结算 N 计划 → 更新账本 → 生成再下一交易日计划，继续循环。

五、关机、补跑和延迟数据的具体规则

例：周一晚已保存周二计划，周二与周三电脑关闭，周四晚开机。
• 周二：可用后来取得的周二数据结算周一晚的既存计划，计划原文与生成时间不变。
• 周三、周四：若没有事先保存对应计划，记“本机离线，无新计划”；仍计算已持仓的收盘估值及应有权益，不能事后让 LLM 决定这两天买什么。
• 周四晚：按日期恢复到周四之后，再生成周五计划。
• 报告同时记录目标交易日、行情实际取得时间、计划实际生成时间、实际结算时间。因此可以晚算，但不能假装准时运行。

当前方案不做预写多日 LLM 计划、不让过期订单无限顺延。订单只对指定交易日有效；该日因限价未成交就失效。因行情尚缺而无法判断的订单是“待数据”，补齐后仍可确定原目标日结果，不等于把委托延续到后来日期。

若某账户前日尚有不确定订单或会影响资金/股数/净值的未知权益，该账户不生成依赖这些未知余额的新计划。金额与日期已确定、尚未到期的应收不是错误，不因此阻断正常日结或使用已确认现金。其他账户可独立继续。所有账户的页面都保持可打开。

六、最小分层架构：六个业务层与独立模型组件

实际日终顺序：本机调度 → 数据准备 → 按此前冻结计划模拟执行 → 账本提交 → 更新页面 → 策略生成下一交易日计划。更新页面失败单独记录，不回滚已提交结果，也不阻断已具备输入的后续步骤。生成今天结果与生成明天计划是两件事，不能把事后策略判断放到今天成交之前。
模块依赖：策略、执行、账本和展示通过数据层公开读取接口使用事实；策略另外读取账本确认的账户状态。调度层组织调用并传入所需证券、日期和用途。数据层不反向依赖这些业务层，也不通过它们才能运行。LLM 策略通过独立 models 组件调用模型服务，其他业务模块不直接依赖供应商 SDK。
策略、执行、展示使用账本公开账户/计划/成交/日报契约；调度还使用其待办和持久化接口。流程层传递公共DTO，执行计算器不导入账本存储，账本也不导入策略/执行/展示/调度实现。不存在相互直接写库的循环依赖。

当前分层依赖（使用方 → 被依赖方；不是每日执行顺序）：
调度与流程 → 数据、策略、规则与模拟执行、账本、展示。
策略 → 数据、账本；只有LLM策略 → 独立模型组件。
规则与模拟执行 → 数据事实、账本冻结计划及资源契约（由外层读取并注入DTO）。
账本 → 数据；展示 → 数据、账本。数据与模型组件不反向依赖其他业务层。
application包括策略/执行子流程及workflow统一编排，scheduler保存纯日程、journal、锁和launchd维护；二者不另立第七业务层。domain/common是共享类型与纯函数；纯验证器/撮合器不直接查询数据库、不调用策略。可渲染依赖图见docs/implementation-status.md“分层依赖关系”。

同一时刻只有一个写账进程；持锁进程退出后操作系统释放锁。启动时检查未完成步骤，凭事务状态恢复，不靠永久的“某人待批准”标记。无需聊天窗口、Codex 调度或 LLM 调度。

2. 数据层
负责免费来源适配、缓存、增量更新、标准化和基础校验；输出有日期和来源的价格、股票身份、交易状态、权益事件及指数快照。只能提供事实，不能生成交易指令。
数据层可单独开发、测试、采集和读取，不需要账户已初始化、策略已实现、模型已配置或页面生成成功。只依赖自身配置、公共数据类型、运行环境、存储以及采集时的网络；不导入策略、模拟执行、账本或展示的业务实现。调度尚未安装时可直接调用数据命令，已有合格缓存可离线读取。
内部分为“源适配”和“业务数据服务”：源适配器负责具体免费接口；业务服务负责标准化、校验、索引、补缺和快照。外层只使用业务服务，不自己拼逐股 JSON 路径，不直接调用源 SDK。统一接口是单机 Python 接口即可，数据层不增加 HTTP 数据服务、消息队列或云端业务组件；独立publishing层仅向云端发布静态展示包。
写入接口接收证券集合、日期范围、用途和预算，返回完成情况、缺口及下次允许重试时间；只读接口按证券、目标日/截止日、用途、快照版本返回事实与明确缺失原因。持仓、未结订单和权益相关代码由调用方传入，数据层不直接查询账户数据库来猜取数范围。
数据层保存数据与进度后即完成本步骤；进度页由展示层或外层入口另行生成。网页失败只产生报告警告，不改变数据成功结果；后续只重建页面，不重新下载。该解耦已经实现，独立 python -m china_stock_sim.market 入口完全不导入展示层。
基础候选池的资格/流动性筛选可在数据层维护；账户相关选股、收益/波动指标、排名、仓位和买卖意图属于策略层。数据层负责提供正确的调整价格序列、目标日状态和权益事实；成交合法性判断属于执行层，持仓权益资格、应收、税款及资金变化属于账本层。

3. 策略层
统一输入为已确认的账户、候选股票、截至 D 的特征和规则参数；统一输出为 N 的买入/卖出/持有意图与理由。S1、S1-LT 用代码；只有 LLM 策略调用模型。模型没有写库、记账、改规则、执行命令或自由采集数据的权限。

4. 规则与模拟执行层
完整细化见docs/execution-design.txt。盘前validate_plan把意图转成可执行订单；盘后match只读取账本冻结计划、原资源及目标日事实，输出结果。负责整手、预留需求计算、可卖股数校验、涨跌停、限价、停复牌、费用、成交模型和当日订单上限。完整计算器已实现并通过隔离跨层验收，冻结订单不会因补跑重选股或改量改价。预留的原子保存/释放和余额唯一事实属于账本；执行计算后经流程层提交账本。成交取决于事先规则与目标日事实，不再调用模型。
2026-10-29设计复审已确认现有数据3项、账本5项依赖足够。已在原执行附件修正：有独立充分未成交证明时不被无关未知阻塞；逐单使用资源守卫，不用视图顶层等待封锁全部订单；提交卖出及评税后重读视图再算未决买单，有进展继续、无进展保存待办退出；整计划状态查当前完整订单，不能把子批次成功或冻结原文状态当完成。逐股规则上下文、覆盖原件异常、默认只读命令不freeze及DTO映射同时明确。均为现行接口的消费约定，不新增数据/账本能力；执行器及T01—T30已在2026-10-30完成开发验收。记录见logs/execution-build-2026-10-30-verification.json；此前复审见logs/execution-review-2026-10-29-verification.json。

5. 账本层
SQLite 保存现金流水、持仓批次、订单、成交、权益、每日净资产和运行状态。金额采用 Decimal 计算及整数分保存，股数采用整数。各账户逻辑隔离，事务按账户提交。
完整范围见docs/ledger-design.txt的L01—L24：另含观察起点、计划封存、资金/股数预留、FIFO成本、分步权益/红利税、估值质量、查询、幂等恢复、更正、备份，以及模型尝试/多日调仓的持久化。原L01—L24范围已在当前代码落地并验收；执行消费者新增LX01—LX05已按账本附件第十六节补齐并验收，不拆阶段或另建版本。未知零碎股分配单独记精确应收待核，不变成可卖整数持仓。账本对提交的交易约束、费用和证据进行防御性校验；独立撮合计算器已完成隔离跨层验收，三策略独立应用已接入，日常调度已实现，WF验收已通过。

6. 展示层
生成无外部依赖的静态 HTML 与 CSV。资金、持仓和成交读取账本；数据准备状态和大盘行情通过数据层公开读取接口取得，不自行采集。页面失败可以从同一账本与数据快照重建，独立记录展示错误，不触发重新采集、重新记账或重问模型。固定地址保留最近成功页面并显示更新时间，本机无需网页服务。运行首页使用独立轻量只读状态投影，不以完整交易报告链作为刷新入口。
交易页主题与运行首页统一：蓝灰配色、首页字体、卡片及双向导航在本机和云端一致。纯、幂等apply_ledger_theme可处理已有HTML，只改外观，不改report-data、金额、订单/成交、生成时间或独立CSV/完整审计；无需为样式重新生成账本或业务数据。此项DS01—DS05的实际验证、部署与浏览器结果按dashboard-style-2026-11-02新证据记录，不借用此前云部署验收。

同协议切换模型/服务只需调整模型配置及本机连接参数；不同协议增加适配器，不修改账本、撮合和数据层。当前 provider=openai_compatible、model=qwen3.8-flash，地址和 API 密钥不入 Git。.env 仅按 KEY=VALUE 解析、不执行 shell，系统环境优先，权限为 0600。model-check 默认只核配置；--live 显式发送一次非敏感测试提示，无自动重试。doctor 不调用模型。业务中只有 LLM 策略使用该组件，实际启用及请求结果以当前状态和模型审计回执为准。
调用云模型 API 不等于部署云服务器：程序和账本继续在本机，但模型调用依赖网络且可能计费，不能保证免费。免费数据渠道的限制保持不变。

以后调整选股、调仓或提示词，通常只改策略层配置；替换行情来源主要改数据适配器。交易规则、费用、权益、账本字段等变化仍需改其所属层，不能承诺所有变化都只修改策略层。

七、免费数据的最小范围与故障处理

数据层只使用本仓库：首次准备保存在 data/raw/baostock、data/normalized/preparation、data/state/preparation；共享事实与任务索引在 data/state/market.sqlite3，原件对象在 data/raw/market，冻结快照在 data/normalized/snapshots。账户仍在独立 ledger.sqlite3。当前免费源：BaoStock（日历、证券、未复权价及分红），东方财富（已公布分红送转，包括未来/未定日事件），腾讯（个股价格备用、三指数）。三个适配器均已真实验证；来源可能延迟或变动，逐次返回状态，不能保证永久可用。腾讯缺少的前收、停牌/ST或指数量额字段保留未知，不冒充完整执行输入。

交易日历同时服务历史窗口与下一交易日计划：保存已经公布的未来交易日，提供前/下一交易日、区间与月末判断；未来日历缺失明确等待，不能用自然日加一替代。已有有效行情按证券、日期和版本复用，日常只取缺口；不把每天重建一个首次准备版本当作增量更新。

固定采集日程（北京时间）：命令2=data-sync，每个交易日18:10后执行；命令1=prepare-data，首次准备之外，在每月最后一个交易日18:10后执行，用于更新候选池。月末按来源交易日历判断，不按自然月最后一天或固定30/31号判断。月末当天命令2照常执行，换池任务不能替代日常增量。调用顺序为先维护D日生效池及必要证券/日历，再执行月末准备；后继池在下一交易日N生效；选池发布失败保留原池，已冻结/发布新池的历史/权益缺口保留该池及待办按用途等待，不回退重选或宣称完成。data-sync在不显式传代码时只读取as_of当日生效池；N日计划所需新池输入若尚缺，应从prepare-data结果取得新池代码，显式传给data-sync/DataRequest补齐，行情截止仍为D，不能提前采集N日行情。来源缺口按规则续跑，各采集任务顺序写入。完整操作约定见docs/first-preparation.md“日常与月末采集日程”。现行workflow已组织定时触发、重启恢复和月末编排，WF01—WF32已验收；记录日程及程序完成不表示生产自动任务已经安装。

股票池采用当前沪深主板中一个明确、可追溯的小池：启动时依据已取得的主板身份、资格和近 20 日成交额，选择不超过 100 只流动性较好的股票；代码排序作为并列裁决。记录池版本与实际选定时间，首月固定池，月底有足够数据时再换池。候选缺数据可排除并解释；没有必要为未参与的数千只股票阻断已具备条件的账户。当前按上述候选池范围采集和评估，不将未参与的全市场数据作为启动前提。

股票移出候选池后，已有持仓、未结订单和未付权益仍持续取数，不能从账本消失。规则策略在下一次有效计划中安排退出已出池持仓；无法成交则继续持有并报告，不强行清零。合格候选不足 10 只时，按实际可用名单操作，其余资金留现金，不为凑数量跳过资格或历史窗口要求。
月末新池按明确日期切换；选池发布失败保留原池，已发布新池但历史/权益补缺未完则保留该池及待办按用途等待，不回退重选；不因某次请求失败或某股下载较快而重排已经冻结的池。资格已明确筛为空时直接报告空池和排除原因，数据字段异常造成的未知则报告待数据，二者不可混用。

S1/S1-LT 保留原选股公式，需要 121 个交易日价格和 60 日波动；首次一次性取足窗口，之后增量补当天。LLM 只需短期特征，若长窗口尚未准备好，可以先启动 LLM 账户，另外两账户显示“等待策略窗口”，不伪造排名。三个账户和页面均已存在。

采集优先级：已有持仓与未结订单 → 必要权益/资格 → LLM 候选和两个规则策略窗口 → 大盘指数与其他展示数据。指数缺失只影响大盘卡片，不能冻结账户。

标准字段：交易所＋证券代码、交易日、开高低收、前收或除权参考价、成交量（股）、成交额（元）、交易状态、是否 ST、上市日期；权益字段按事件类型另表。保存 provider、fetched_at、源内容摘要和原始响应定位。不能把手与股、千元与元混用；不能用最新名称直接证明历史身份；行情日期必须与目标日一致。
统一数据快照绑定价格截止日、实际取得/可用时间、池版本、标准化版本和依赖文件摘要。消费时核验完整性，缺失或损坏不得继续使用“上次准备完成”的布尔值作为证明。来源后来订正则保存新版本，旧计划仍引用旧输入；需要更正账务时由对应业务层显式处理。
可用性按证券、日期、用途分别判断：可估值价格、LLM 短窗口、规则策略长窗口、执行所需事实、权益事实和指数。数据层只能证明某种输入可用，不能单独宣布账户可交易或完整系统已启动。缺一个股票长窗口或缺指数，不阻断其他已经具备条件的用途。
采集任务的state_scope固定为requested_fact_collection_not_trading_readiness；COMPLETE仅说明本次请求的价格、指定权益覆盖及指数采集完成。请求指数缺失时任务为PARTIAL，但个股用途仍独立可用，不因此冻结账户。任务逐股保存prices/events/event_coverage及问题，顶层event_conflicts列出冲突；来源冲突可与采集覆盖完成同时存在，不能凭任务完成状态结算或成交。
目标日资格和价格限制事实必须有适用日期与依据，未知不套默认值。权益视图既包含已生效事件，也保留决策时已经公告但未来登记、除权或到账的事项；无明确日期的已知事项不能默默删除。只补相关证券的必要事件和证据，不预建全市场多年完整权益数据库。

基础校验：键唯一、价格为正且低≤开/收≤高、量额单位明确、缺值显式、异常价变检查。成交和估值用不复权价格；策略复权序列必须以当时已知权益构造并冻结，不能事后覆盖旧决策输入。缺失行情不等于停牌；已知停牌的无成交记录可以有沿用价格，但不能据此撮合。
关联校验还包括量额相互一致，以及已经用于选池与历史输入的两个接口在共同证券日期上的一致性。发生冲突保留双方原文，隔离受影响证券或用途，不静默选一个值。跨日突变应结合除权和状态核对，不把每次价格跳变都当坏数据。

常规响应分类：成功 / 暂未发布 / 临时网络错误或限流 / 格式或数据异常 / 源间冲突 / 本地缓存损坏。可重试的网络/暂未发布错误按连续失败计数retry_failures选择1、5、15分钟退避，连续失败超出档位后保持末档；attempts只累计实际源请求用于审计，历史成功次数不参与失败退避。校验成功清零retry_failures；预算/来源冷却暂停、主动中断及遗留运行状态转PAUSED均不增加该计数。旧记录缺retry_failures时，已知OK从0开始，无法区分历史成败的失败/中断记录保守沿用原失败档位，下一次可信成功后清零。已保存的next_retry_at与server_retry_at不追溯缩短或改写；HTTP Retry-After仍遵守，取不短于服务端要求的等待。单次来源请求使用配置上限45秒与剩余采集预算的较小值；HTTP open原样使用调用方传入的剩余timeout，不另设隐藏10秒截断，外层可杀子进程保持整个请求的硬deadline，分页不重置来源总预算。单次联网流程默认最多30分钟活动时间，达到后保存进度和下次允许重试时间，由调度再次调用；直接运行数据命令也可以续跑。数据层不依赖安装后台调度才能实现恢复。格式错误不高频重试，转已验证备用源或标记需要适配。缓存修复隔离损坏原件、保留修复记录和版本关系，不静默重选池或改旧计划。成功内容不重复下载，不绕过访问限制。事件某一路失败时，其他已成功源缓存须满足本轮目标日18:10后的取得时间且不晚于查询时点，才可复用；读端递归核验原始依赖，不能用合成时间替代原件时间。跨日或显式refresh会复查，服务端冷却不会被刷新绕过。同源连续3次网络错误后本轮冷却60秒，备用源继续，到期探测；中断及持唯一写锁后识别出的遗留运行状态保存为PAUSED。

不强求每条正常行情双源逐字段一致；可疑价格、单位或权益才按用途交叉核验。有明确冲突且影响成交/资金的证券保持待核；其他账户不受牵连。缺全池历史数据不会阻断已经初始化的账本页面。

模型按本机公开配置指定的角色、模型名与OpenAI兼容接口接入，连接参数仅保存在本机；当前配置和连接维护的权威说明见docs/model-layer.md，非敏感连接实测按对应日期回执确认，不把早期服务商或地址当作现行连接。结构化计划、校验及隔离封存闭环已实现；正式策略调用及冻结结果以本次真实运行回执为准，单次连通不表示交易策略实际运行。默认max_output_tokens=2048；两次调用共享首次占位起算的默认120秒总时限与N日08:59:50上界，生产调用以可终止子进程落实硬截止。以后可通过独立模型适配组件切换服务，也可另接本机模型；当前不要求下载本机模型。模型推理可能计费，免费数据要求不变。

九、交易时间、限价与成交规则

当前方案固定为 NEXT_SESSION_DAILY_OPEN_V1：前夜定好，下一交易日用开盘价参考判断。模型或规则策略必须在截止前明确代码、方向、数量、限价、顺序、目标日期和最大资金；保存计划哈希、生成时间、输入截止日、账户状态版本与策略版本。

买入：股票属于允许范围；原计划合法；有有效目标日行情；并非已知全天停牌；目标日开盘价≤事先买入限价；不是本模型拒绝的涨停买入；现金足以支付数量×成交价＋所有费用。全部满足，按开盘价模拟成交。

卖出：具备足够可卖股数，买入批次的交易日早于目标交易日；有有效行情；开盘价≥事先卖出限价；不是本模型拒绝的跌停卖出。满足后按开盘价模拟成交。

保守约定：开盘价等于涨停价时不模拟买入，等于跌停价时不模拟卖出。实际市场在涨跌停价可能成交，本系统不凭日线假设自己排到队；涨停卖出或跌停买入也不能一概说法律禁止。日线量大于零不能证明本订单真实可成交，报告始终标记“模拟成交”。

限价按 0.01 元最小价位规范；买入 100 股整数倍，卖出依据可卖批次且零股余额一次性处理。采用目标日适用的涨跌幅和除权参考价校验，普通主板通常为 10%，但不能对特殊日期、特殊状态机械套用。现行2026-07-06起适用的普通主板/ST幅度、无涨跌幅特殊日及价格最小变动保护按官方规则包确定。已知无涨跌幅日当前开盘模型买卖均明确不模拟；规则/特殊身份未知则待核，不能当普通10%。普通限价单买卖单笔上限1,000,000股；不自动拆单。未来复杂事项的买入排除只采用盘前已知证据，盘后只补核目标日实际生效事实，不用后来公告反改原单。

现金处理采用简单保守规则：今天开盘买单只能使用此前已经确认的现金，不能预支今天同一开盘卖单的收入。冻结计划时按所有买单的限价金额＋费用预留，预留不等于现金实际扣减；成交才记流水。卖出所得进入当日现金，从之后一轮新计划使用。盘前冻结账务提交顺序为SELL→税负评估/待核→BUY，同方向保留策略顺序，用于避免买入先花钱、卖出后才发现未知税负；这不是模拟真实逐笔顺序，也不开放卖款使用。每单提交事务重验守卫，不能只更新修订号复用过期账户输入。

不满足限价、明确停牌或有证据明确不支持的交易日：记录具体未成交原因，不产生手续费。盘前资金/可卖股数不足拒绝建单；冻结后原资源/批次或新增税负无法确认则资源待核，不能用后来现金补足旧单。价格/状态/权益缺少到不能判定：标记 WAITING_DATA，而不是说交易失败或收益为零；后来只补核原计划。已确认订单可以逐笔提交，但账户日结仍标记未完成，并继续保留未决买单资金预留，暂停依赖不确定余额的新计划。

当前方案订单全额成交或不成交，不模拟部分成交、盘中追单、自动改价、涨停排队、日内止盈止损。采用开盘价参考、暂不另加滑点或冲击成本，页面明示这项近似；未来新增滑点必须调整执行版本，并遵守限价及合法价格范围，不能重复扣一遍费用。

为什么不采用日内最高最低价？因为日线不能给出高低点先后和触价成交数量。以后确需限价触发模式，可另设预先固定的模型；当前方案不混用多套撮合标准，也绝不事后挑当天最低买、最高卖。

十、费用、资金公式与权益

默认模拟费用沿用项目已有假设：全佣万三，单笔最低 5 元；同一账户、股票、方向和交易日只形成一笔逻辑订单，不人为拆单重复触发最低佣金。全佣含所假设的交易所相关费用，不重复叠加。它不是用户实际券商报价。
卖出印花税：成交额×0.0005；买入不收。
过户费：买卖双方各成交额×0.00001。
每项按 Decimal 四舍五入到分；费率配置带生效日期，页面列出版本。官方标准发生改变时按新生效日更新，不能用新税率改写过去的账。

现金期末 = 现金期初 − 买入成交额 − 买入费用 + 卖出成交额 − 卖出费用 + 实际到账权益 − 实际扣缴红利税。
可下单现金 = max(0, 已确认现金 − 未决买单资金预留 − 其他明确应付预留)；若不能覆盖已知负债，另列资金短缺并禁止新买，不以负数现金融资。
持仓市值 = Σ（持仓股数×目标日不复权收盘价）。
账户权益 = 现金 + 持仓市值 + 已确认应收权益 − 已确认应付税费。
累计盈亏 = 账户权益 − 本账户初始本金；没有出入金时，当日盈亏 = 今日权益 − 上一交易日权益。
净值 = 账户权益 / 本账户初始本金。费用已进入现金，不再从总资产重复减。按 FIFO 管理卖出批次、成本与持有期限；交易费计入对应成本/收益计算，页面的现金公式可独立复算。

演算示例（纯说明，不是真实成交或现有账户结果）：
50,000 元以 10.00 元买入 1,000 股：成交额 10,000，佣金 5，过户费 0.10，余款 39,994.90。
当日收盘 10.20：市值 10,200，总资产 50,194.90，累计盈亏 +194.90。
下一交易日若以 10.30 元卖出全部：成交额 10,300，佣金 5，印花税 5.15，过户费 0.10，净到账 10,289.75，最终现金 50,284.65，持仓 0，累计盈亏 +284.65，累计费用 15.35。

权益不能全部省略，否则持仓遇到分红送转后账会系统性失真。当前方案对已有持仓、拟买候选、未结订单及仍有未完结权益或税款的证券做必要处理，清仓不停止待办维护，不先补齐全市场几十年的全部公司行动：
• 现金分红以权益登记日持仓确定资格，在除息日确认应收，到账日转现金；不能在登记日把含息市值与应收同时计入。除息与到账不同步时不能把应收漏掉，也不能提前把应收当可下单现金。
• 送转股以登记日持仓确定资格，除权日记录应收股数及对应价值；本项目保守采用已确认股份上市日作为日级交付/可卖日期，转为持仓不重复增加资产。原股与新增股份分配原有总成本，原股先售后仍保留应收成本。非整数权益保留零碎股分配待核及暂估，不自行补成整数或折现金。税务起点与成本来源、可卖日分开记录。
• 红利税按FIFO和自然月/年记录适用税档、税基、应付及扣缴；确认负债和实际扣现金不能重复减资产。送红股面值/资本来源未知不得猜值；已出售但无法核税是未知负债，净值暂估并限制相关新计划；尚未出售的潜在差别税负单列。项目在出售与分配实际发放均发生后的下一交易日模拟扣缴，缺现金保留欠税，具体规则及官方依据见账本附件第八/十四节，此时序不冒充券商实际扣款日。
• 当前方案不主动参与配股、复杂重组和退市处置。已知相关候选不新增买入；持仓突发事件则保留持仓、隔离受影响证券、报告应收或估值待核，不自动清零。无足够事实时，相关账户不能发布确定的最终净值或新增依赖未知资金的计划，其他账户与页面继续。

权益维护恢复（B22已实现并验收）：resolve_tax_holding_rule只按configs/tax_holding_rules.toml中有官方依据、生效区间与明确起点方式的规则恢复RULE_PENDING批次，保存不可变规则证据、重算未知税务并标记历史账单修订；默认空规则/UNKNOWN不猜日期。resolve_event_identity依据同cutoff公开证据把无经济记录的疑似案归并为稳定案别名，保留MERGED追踪；多个已记账案不自动归并，已确认金额也不静默覆盖。两入口复用账本事务、幂等及CLI，不调用LLM、不改变命令1/2或历史数据。

执行消费者补充：数据D18修正特殊状态上下文与涨跌停精度/一tick边界，D19保留前日错误及日历证据依赖，D20将明确未来复杂事项与目标日价格用途隔离；均已实现并验收。账本已新增一致execution_view区分原资源和当前提交守卫，绑定实际DTO/账户快照/冻结政策，补齐未成交原因证明、WAITING重复批处理状态及中立费用算法。逐项缺口见执行附件第十一节和账本附件第十六节。行情总量只作零量/原全量订单超过全日量的否定检查，量缺失待核，不假设开盘流动性。

稳定运行首页为reports/index.html，reports/forward_current/index.html为交易看板；仓库根目录“前向模拟.command”轻量刷新并打开首页。运行节点与财务展示各司其职，交易看板从实际账本读取观察起点、冻结计划、订单、成交及账单。现行展示契约见interface-design的TU01—TU12及TH01—TH10，账本依赖与个股损益口径见ledger-design第二十二节；真实发布及浏览器验收以唯一当前入口和本次收据为准，不由设计文字代替。

“交易计划与实际执行”按交易日选择，联动该日计划、成交、关联行情和该日个股当日盈亏；账单日期纳入选择，未来未日结不回退最新账单，边界前序仅作为计算依赖。计划显示股票代码/已有名称、方向、数量、限价、理由、执行状态和实际冻结时间；成交显示实际日期、价格、股数、金额、费用、净现金及已记录的已实现盈亏。已终态订单采用最终result/订单原因，不能被历史last_attempt的等待说明覆盖；未终态保留最近尝试。无订单、待执行、未成交和已成交分别解释，不把零成交当作失败。

计划参考行情采用plan.market_as_of，目标交易日行情采用target_session，实际成交行情采用effective_date，分别标明用途与日期、开高低收及前一交易日已保存收盘价。只读取本地已有行情，目标日缺数据时明确尚无该日数据，不拿参考价顶替目标日价，也不冒充实时价格。缺名称时保留代码。

“当前持仓与买入成本”固定标明最新账单估值日，不随上方日期改变；含费成本均价＝剩余成本÷剩余股数。逐股展开仍有剩余数量的原始买入/权益批次，分别显示原成交与估值日剩余数量、成本；按批次变动重建并与账单核对，不混用后来交易后的live lot。可卖数另属当前快照，股份应收独立列示。个股当日盈亏已移入日期联动区，只有连续最终估值和可归属现金/经济事实充分时计算，缺证为待核；账户差额不分摊。

“已清仓股票与完整买卖历史”独立折叠，按股票/当前持仓状态筛选；全生命周期累计买卖与逐笔成交各20行分页。清仓后回购仍属当前持有且旧成交保留，权益或税款未结单独分类。卖出已实现按保存FIFO成本和明确归属更正计算，不称含分红税款的终身收益。完整历史CSV与页面同快照；历史JSON独立于report-data、不重复原件、不请求旧行情。每账户一次窄经济字段投影，单数组≤1000分块；10MB/50MB发布上限明确失败保留上次完整包，不静默截断历史。

资金趋势分为两幅静态图：总资产/现金/持仓市值图和累计盈亏图。横轴标交易日期、纵轴标人民币元，具有数值刻度、图例、零线/适当范围及点位提示；缺估值断线，不画成0，空数据、单点、持平和负值都有解释。图下保留准确账单数字和资金公式。

每日资产与资金计算、现金流水、权益与税款、运行恢复记录、大盘行情、历史缺计划说明，以及账户登记/冻结身份/决策审计分区折叠。每日账单CSV、本账户中文审计和冻结计划审计JSON入口保留；完整本机审计不上传云端。人读正文使用中文状态与原因，未知枚举显示待解释并保留原码于审计；机器JSON/CSV仍保留既有原码。云端保留同一公开业务结构与允许的折叠区，仅分离完整敏感审计。

MISSED_CUTOFF必须指出其target_session及该日09:00的新规划截止；历史缺计划不冒充当前账户或选中日期的资金异常。已有该日冻结计划优先展示其执行状态，不能因当前已经过09:00而变成缺计划。账务、估值、计划及报表状态仍相互独立，无计划或0成交也可正常日结，未知盈亏不能填0；页面失败不改变已经提交的账务。

交易看板读取最近60个交易日和未决关联，显示范围说明；展示层仅对关联代码/日期做有界只读查询，跨账户复用行情缓存，不展开巨型输入、采集行情或改变策略政策。完整实际成交另通过同一只读事务的include_trading_history窄投影显式取得；完整冻结审计仍走原显式入口。图表及展示计算不成为另一套金融账本。

十二、最少但不可省的工程保护

• 单写者锁：调度和手工启动共用同一把操作系统锁；已有运行时后来的进程退出，不并发扣款。
• 幂等：账户＋目标日＋计划编号唯一，订单和成交 ID 唯一；同一数据重跑，现金、股数和费用不变。
• 等待与完成分开：WAITING按尝试记录，不消费终态入账唯一键；新证据可确认同一原单。实际封存时间由账本产生，不能由调用方倒填；运行时间等变化不改变业务幂等摘要。
• 原子账务：成交记录、现金流水、持仓变更在一个 SQLite 事务内提交。中断前未提交则回滚，已提交则恢复时识别并跳过，不以文件存在与否猜是否扣款。
• 顺序恢复：每个账户按交易日推进。处理中断、重试和报告重建不重新调用已经成功封存的 LLM 计划。
• 状态检查：现金不为负、卖量不超可卖量、资金公式和资产组成一致、计划早于截止、输入不含目标日未来行情。通过普通代码执行，不用 LLM 审批。
• 可重建报告：先提交账本，再由展示层读取账本一致快照生成临时页面，成功后原子替换稳定页。渲染失败保留旧页和失败状态，恢复后重新生成，不重做交易。
• 展示恢复：财务修订号与展示修订号分开；下一日计划、模型失败或步骤错误也产生待发布状态。保存last_rendered_revision，崩溃后能补发最新页面，发布回执不触发无限刷新。
• 数据修订：已发布日线后来变更时存新版本，不静默覆盖已记账结果。需要调整的历史成交通过显式更正记录、关联原单与受影响日计算体现；不得重选历史股票或重问 LLM。
• 备份：每日完成后用SQLite备份接口生成本地滚动备份及校验摘要，不在运行中直接复制可能不完整的数据库文件。只将COMPLETE计为完整成功，保留最近30份完整成功日备份；连续PARTIAL不能挤掉最后完整备份。审计的账户状态和证据清单来自同一只读事务，避免跨提交混读（B23已验收）。本机同盘备份能防误写，不能承诺硬盘损坏后可恢复。
• 运行观测：workflow/homepage/upload三任务调用在logs/runtime/YYYY-MM-DD/<invocation_id>.jsonl逐次保存START/阶段/END与单调耗时、CPU增量、终生峰值RSS及业务关联；原journal、stdout/stderr和金融原件各司其职。源码原字节以data/normalized/runtime-evidence/objects/*.evidence内容地址保留，data/normalized/runtime-evidence/identities/*.json保存摘要与脱敏配置语义，不能作为另一套可执行版本。运行明细30天/压缩归档180天按完整保护清单受控维护，源码审计与唯一金融证据不套用日志期限；缺失/损坏/中断明确显示。只读runtime-history及runtime-archive-verify不执行业务；runtime-archive仅在data/backups/runtime显式保存运行证据压缩包，保留原件。首页刷新后的archive_due使用独立非阻塞锁、单日期及扫描/字节预算，内容指纹变化时追加新归档；超限待手工、失败续办，不占业务锁。auto-state游标优先尚未建包日期，否则轮询已归档日期，每次仍最多一日期，避免新日期饥饿。记录器或归档失败不改变业务结果，不跳过金融完整性校验。该同盘归档不是全项目备份或异机容灾，准确范围和RO验收见docs/runtime-observability-design.txt。

账本完整逻辑结构及迁移见附件第十一节：账户/现金流水、计划/订单/预留/成交、批次/变动、稳定权益事件/应收/税款、日资产/持仓、幂等操作/业务步骤/模型尝试/调仓任务，已在当前程序实现。此前生产库经1→2迁移达到19表，保留原三笔本金、ID及时间；2026-11-01的SL schema3增加政策/决策两表，该次生产2→3先备份再完成，该次迁移保留原19表逻辑摘要，当时新增3条base政策、0条决策，没有删库或重注资；后续正式运行按公开接口追加政策、决策与业务。行情仍在独立数据层；data/plans保存冻结计划及脱敏模型响应，数据库保存关联，fills只保存确定模拟成交。备份通过数据公开evidence_manifest取得市场证据依赖清单，缺原件时明确报审计不完整；恢复只写新的隔离目录。

运行过程状态：发现待办 → 采集/复用数据 → 核原计划 → 结算 → 对账 → 发布今日页面 → 生成并封存下一日计划。每步都有成功/待数据/失败状态和 last_error；账本成功而模型失败不回滚今日账本。

正式运行独立性：试运行允许开发者或助手检查并修改程序；正式运行不得依赖聊天助手在线值守、全程监控、核验或修正。只有LLM策略生成买卖计划可以调用模型；采集、标准化、校验、重试、续跑、缓存恢复、故障隔离、记账、报告及调度均由确定性程序完成。超出预设恢复范围时保存证据、暂停受影响项并展示原因，不自动交给LLM排错或编造数据；需要代码适配的异常留给维护阶段处理。机器关闭时无法执行，重新启动后由现行workflow根据权威水位恢复。数据层已独立，账本业务已实现并已通过统一验收；独立撮合及提交恢复已完成；三策略独立规划/发布/恢复已实现；完整业务调度已实现并验收通过；生产无人值守的实际开关、安装和运行结果由唯一当前入口及回执记录。

十三、规则更新和版本管理：取消日常人工批准链

只维护一个当前可执行版本和一份明确配置。行情接口版本、交易规则生效日、策略版本分别记录，不再让交易程序对采集程序的所有源文件逐个绑定，导致改一次网络重试就拒绝整个交易入口。

程序依赖和发布包仍固定版本；升级在无运行任务时完成，数据库迁移先备份并检查，失败保留可恢复状态。正常重启不建新账户；策略调整从明确的未来交易日起生效，旧计划、旧交易和旧策略版本保留。

交易规则/税率用有效日期配置。每周可由普通程序检查官方规则页面的变更线索，但页面没访问成功不等于当前有效规则七天后自动失效。取消每七天让多个 agent 重新批准同一套规则的流程。已识别的真实规则变更需要发布配置更新；机器不能可靠理解的新规，明确提示维护并限制受影响的新订单，不让 LLM 临时改账务规则。网站版式变化本身不直接冻结所有账户。

本轮联网核实沪深交易所已有 2026 年修订的交易规则，7 月 6 日施行，不能把项目早期引用的 2023 版自动视为当前全文。实现时以现行有效条文、暂缓条款和适用范围建立精简规则表；不把整份法规逐日重新审核作为运行条件。

十四、哪些复杂设计先省略

从当前方案日常链中移除：云端业务运行、业务日包跨端往返与签名（独立两页静态发布及09:00/21:00推送按publishing现行契约保留）、09:16/09:18竞价原件采集、证明普通股票全天每个时段都正常的门槛、每个日包多 agent 审批、每周 LLM 规则续签、全市场历史研究验收、六候选模型比较、自动策略优化、分钟行情/盘口排队、精确成交概率和自动盈利晋级。

保留：免费来源真实数据、明确时点的不可回写计划、股票资格、T+1、整手、合法价位、有限现金、必要权益与费用、可恢复账本、明确失败原因、稳定页面。放宽的是工程和盈利门槛，不是虚构成交或忽略资金错误。

十五、整体建设范围和真正的启动验收

只维护一套完整建设方案，不按多个阶段/版本删减必须功能。数据D01—D20、账本L01—L24/LX01—LX05和执行X01—X24/T01—T30既有范围已实现验收。策略/账户方案的8项支持SD01、SL01—SL04、SM01、SX01、SI01均已完成各自验收，SL-C01—SL-C20全部PASS；ST01—ST30、AC01—AC08完整业务已接通，独立闭环及恢复专项通过；三策略SA01—SA30完整验收已通过，整体调度与流程已实现，WF01—WF32全部验收通过。策略、账本、执行附件共同细化本文，不是另一个架构。

整体验收需要数据公开服务、规则/模型计划、执行验证器、账本事务、页面和普通程序调度贯通。测试输入与真实前向账隔离；原件、账户与入口只在本仓库，不能借旧工程结果证明现有能力。开机/唤醒后的程序恢复与不依赖聊天助手值守须有验收证据；本轮已验证真实隔离LaunchAgent触发及持久恢复，未做物理睡眠或重启实测，准确边界见workflow附件。

完成开发不等于已有真实时间运行结果：须在未来交易日开盘前保存计划，目标日结束后以真实行情结算，并生成下一日计划，至少完成一个真实周期才称“前向闭环已启动”。无成交可完成业务周期，但不能声称已验收真实行情驱动的模拟买卖；有合法机会时另核首笔买卖。账本完整验收矩阵见附件A01—A20，以下是整体共同标准。

最低验收场景：
1. 初始本金、交易费用与示例资金公式能逐分对账。
2. 买入当日不能卖；整手、现金生效；LLM 每日最多 5 代码，S1/S1-LT 无每日代码截断；旧冻结政策按原范围执行。
3. 停牌、涨停买入、跌停卖出、价格未到及无行情分别有正确状态。
4. 同日重复运行、中途强制结束再恢复，不增加重复成交或费用。
5. 关机多日只补算已存在计划；缺计划的过去日期不出现新交易。
6. LLM 不可用或返回非法内容，另外两账户、已有账和页面仍可运行。
7. 分红/送转、应收到账和税费不会产生凭空资产增减；未知权益明确待核。
8. 看板任意日期可查资金组成、订单原因及实际更新时间；旧页不会伪装新数据。
9. 不接入聊天助手监控时，断网后按冷却恢复、坏数据局部隔离、重复运行幂等、重启后恢复均由程序完成；模型不可用时，规则策略及其他数据、账务与报告功能仍正常。超出恢复范围的故障有证据、明确原因和受影响范围，不调用LLM修补数据或代码。数据侧相关机制已验收，账本自身恢复、财务和跨层机制已通过统一验收；三策略及完整workflow已接通上述公开能力，WF01—WF32的隔离闭环、故障与恢复验收通过。正式账户启用和首个真实未来周期仍单独记录，不能由隔离验收代替。

业务闭环验收不要求回测盈利、不要求 S1 每日成交、不要求云端运行业务或全天开机，也不以一大堆旧版测试数代替上述实际闭环。独立静态发布的服务器、HTTP及浏览器验收另按RH23—RH24和本轮部署回执核验。
